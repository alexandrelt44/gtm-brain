## Como usar este arquivo

- **O que entra:** o mapa hub-and-spoke de cada página pilar e dos seus satélites. Planos de links internos. Lacunas de conteúdo.
- **Como os agentes leem:** os agentes carregam este arquivo quando propõem um post novo, para saber onde ele se encaixa, para onde ele aponta e qual pilar ele sustenta.
- **Frequência de atualização:** revise a cada trimestre. Um cluster com menos de seis satélites está incompleto. Um cluster com mais de quinze provavelmente são dois clusters.

- [x] Legível por máquina: mapa de clusters numa estrutura de árvore previsível.

- [x] Fonte única da verdade: nenhum outro mapa de conteúdo num documento paralelo.
- [x] Versionado: data da última atualização.
- [x] Citável: os agentes citam `/06-seo/CLUSTERS.md` em todo briefing de conteúdo.

## Modelo hub-and-spoke

- **Página pilar:** de 2.500 a 4.500 palavras. Cobre um tema principal de forma ampla. Tem uma pessoa dona.
- **Satélites:** de 1.000 a 2.000 palavras cada. Cada satélite aprofunda um subtema. Aponta para o pilar. Aponta para pelo menos dois satélites irmãos.
- **Cluster:** um pilar mais seis a doze satélites. Cobre uma disciplina ou um problema de uma persona.

## Regras de links internos

Valem para todos os clusters.

- Todo satélite aponta para o pilar nas primeiras 200 palavras e de novo na conclusão.
- Todo satélite aponta para pelo menos dois satélites irmãos, de preferência dentro do texto e não num bloco de "posts relacionados".
- Toda página pilar aponta para todos os seus satélites numa única seção perto do meio da página.
- Todo cluster aponta lateralmente para pelo menos um cluster vizinho, para que os buscadores enxerguem a estrutura.
- Na Cadência, os clusters 1 e 2 apontam um para o outro pela reposição de aulas (falta que não é reposta vira cancelamento). O cluster 3 aponta para o 1 pela tabela de preços. O cluster 4 aponta para o 2 pela padronização da agenda.
- Todo satélite de decisão aponta para a página de recurso certa (`/cobranca`, `/agenda`, `/presenca`) ou para `/rede`.

## Cadência de atualização

- Toda página pilar é atualizada a cada 6 meses.
- Todo satélite é atualizado a cada 12 meses, ou antes se o tráfego cair 25% ou mais de um mês para o outro.
- Checklist de atualização: atualizar números, conferir de novo as afirmações, trocar prints de tela, refazer a pesquisa da palavra-chave, reescrever a abertura se ela ainda começa com "nos dias de hoje...".

## Como passar este arquivo para um agente de IA

```text
Carregue /06-seo/CLUSTERS.md antes de propor qualquer conteúdo novo.

Antes de escrever:
1. Identifique a qual cluster a peça pertence.
2. Confirme que a palavra-chave principal ainda não foi atribuída a um satélite irmão.
3. Planeje os links internos: para o pilar, para dois satélites irmãos e para pelo menos uma página de serviço ou uma prova.
4. Confira a lista de lacunas de conteúdo. Se o tema se sobrepõe a uma lacuna, preencha a lacuna.

Não publique uma peça sem cluster pai. Se o tema não se encaixa, proponha um cluster novo antes de escrever.

Cite /06-seo/CLUSTERS.md no briefing do conteúdo.
```
